## What you need to arrange

1. Name the operating organisation, privacy owner, safeguarding lead, support and incident owners. Provide genuine monitored contact details and team biographies.
2. Arrange Ghana legal/privacy, child-safeguarding and qualified clinical/SRHR content review. Establish age-sensitive collection/reporting rules. Code cannot grant these approvals.
3. Obtain direct provider confirmation of contacts, eligibility, costs, confidentiality/reporting limits, accessibility, geographic coverage and escalation/review contacts. Document pilot partner arrangements. Automated referrals additionally require signed agreements, training and safety/legal/security approval.
4. Select and fund hosting/domain/managed database after region/contracts review. Supply access securely rather than pasting secrets. Obtain provider prices and budgets for review/support/security. `docs/COSTS.csv` is a quote-pending legacy list, not a completed estimate.
5. Recruit consenting adults for usability/accessibility, commission independent security assessment and approve monitoring/recovery responsibilities and launch gates.
6. Verify official HackLab eligibility/category/deadline and submission requirements. PDF event alignment is proposed; this audit did not establish eligibility or acceptance.

## Commands and deployment limits

Local setup is in [README](../README.md) and [SafeHer setup](SAFEHER-SETUP.md). The app currently runs at `http://localhost:3200`, which is not a public production URL.

For **dedicated synthetic staging only**, configure its approved database, independent vault-managed secrets and exact HTTPS `APP_URL`, using Node 24:

```powershell
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed:safeher
npm run directory:seed
npm run lint
npm run typecheck
npm test
npm run build
$env:PLAYWRIGHT_PRODUCTION='true'
npm run test:e2e:safeher
npm audit --omit=dev --audit-level=high
npm run start
```

Browser tests need installed Playwright Chromium or `PLAYWRIGHT_CHANNEL=chrome`; database tests need synthetic fixtures. Check environment/backup before migrations. Production migrations require approval and separate credentials. Never run demo seeds/reset/tests against real-user databases. Directory seed rejects an expired source snapshot; rerunning it does not renew verification.

Exact vendor/domain production commands depend on hosting/access/region and approvals not yet supplied. Setting `DEMO_MODE=false` today excludes demo-approved lessons, leaving no professionally approved learning/retrieval corpus; privileged access also requires prior MFA enrollment. The publishing flag `SAFEHER_PILOT_REVIEW_ENABLED` is not proof of approval.

Intentionally disabled: sensitive referral transmission, external model calls, public self-registration, unreviewed translations and real-patient onboarding in legacy clinical workflows. Keep these boundaries during staging.
